- (decision) Paradigm: functional core, imperative shell. One pure reconcile(prevState, checkResult, now) -> {nextState, effects[]} is the sole decider of queue contents, alerts, reminders, mascot state. Shell adapters (GitHub, storage, VS Code UI, clock) do I/O only. Binds FR-4..FR-13. Prevents alert/queue logic being decided in more than one place (SM-2 drift). Alternatives weighed: full hexagonal (too much ceremony), feature services (split alert decisions).
- (decision) GitHub access: one GraphQL query per check: search(type: ISSUE, 'repo:o/r is:pr is:open user-review-requested:@me') with per-PR title/author/url and timelineItems(itemTypes:[REVIEW_REQUESTED_EVENT], last:N). Requester/requestedAt derived from latest event naming the viewer; if missing or ambiguous, that item falls back per FR-8/FR-11 while the check still succeeds. Resolves PRD open decisions 1 and 5 (economy). Alternatives: REST N+1 with ETags, REST search only (always fallback).

- (decision) Backlog vs new classification (found during distill): an item first observed is backlog (no individual alert) iff this is the user's first successful check ever OR the previous persisted successful check (from any window) is older than 2x the poll interval; otherwise new. Replaces 'first check in this window = backlog', which would let a newly opened second window silently swallow alerts. Side effect: after long sleep, arrivals become backlog; accepted, consistent with FR-9 intent.
